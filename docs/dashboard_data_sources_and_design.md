# 교육·역량 대시보드 데이터 및 설계 명세

## 1. 문서 목적

이 문서는 `edu-skill-gap` 대시보드가 어떤 데이터를 사용하고, 추천 결과를 어떻게 만들며, 사용자에게 어떤 한계와 이용 정보를 보여주는지 설명한다. 수치는 2026-10-15에 저장소의 현재 CSV를 기준으로 확인했다.

## 2. 대시보드의 범위

- 대상: 인사·조직, 노무관리, 총무·일반사무, 비서·사무지원 및 인접 직무
- 기능: NCS 직무-역량 연결을 바탕으로 실제 수행 업무를 선택하고 교육과정을 추천
- 추천 대상: `INCLUDED`로 검증된 교육과정만 기본 추천에 사용
- 개인화 방식: 사용자가 선택한 목표 직무, 실제 업무, 역량별 현재 수준(1~5), 목표 수준을 사용

## 3. 사용 데이터

| 데이터셋 | 경로 | 역할 | 현재 건수/범위 |
|---|---|---|---|
| 통합 교육과정 후보 | `data/hr/output/integration/hr_integrated_candidates.csv` | 과정명, 기관, 직무 분류, 난이도, 시수, 수강료, 원문 URL, 수집일, 검증 상태 | 553건 |
| 검증된 과정-역량 매핑 | `data/hr/output/integration/hr_mapping_verified.csv` | 교육과정과 NCS 핵심 역량의 연결 | 295행 |
| NCS 직무 마스터 | `data/hr/processed/jobs.csv` | 목표 직무 목록과 직무 설명 | 6개 직무 |
| NCS 역량 마스터 | `data/hr/processed/competencies.csv` | 역량명, 정의, Knowledge/Skill/Attitude, 실무 기술 목록 | 7개 역량 |
| 직무-역량 매핑 | `data/hr/processed/job_competencies.csv` | 직무별 필수/선택 역량과 매핑 근거 | 7행 |

### 3.1 교육과정 출처 구성

통합 교육과정 후보 553건은 공개 API 140건과 민간·공공 플랫폼 SQLite 수집 데이터 413건으로 구성된다. 원문 플랫폼은 9개이며, CSV의 `collected_at` 범위는 2026-09-30 ~ 2026-10-09 UTC다.

각 추천 카드에는 `source_platform`, `source_type`, `collected_at`, 원문 `course_url`을 표시한다. 사용자는 반드시 원문 링크에서 모집 상태, 가격, 일정, 수료 조건을 다시 확인해야 한다.

## 4. 실제 수행 업무 선택지의 생성 방식

사용자가 빈 텍스트 상자에 업무를 작성하지 않아도 되도록, 대시보드는 선택한 직무의 NCS 역량 마스터에서 `skill` 필드를 읽어 업무 선택지를 만든다.

예를 들어 인사·조직 직무의 `인력채용` 역량에는 `면접 기술`, `역량 평가`, `입사 온보딩 기획`이 표시된다. 각 선택지에는 연결된 NCS 역량명이 함께 표시된다. 직접 입력은 목록에 없는 업무만 기록하는 보조 기능이다. 직접 입력한 문장은 현재 자동 매핑에 사용하지 않으며, 근거 없는 추천을 만들지 않는다.

## 5. 개인화 추천 기준

1. 사용자가 목표 직무를 선택한다.
2. 대시보드는 `job_competencies.csv`에서 해당 직무의 연결 역량을 찾는다.
3. 해당 역량의 `skill` 목록에서 실제 수행 업무 옵션을 만든다.
4. 사용자가 선택한 업무를 역량 ID로 변환한다.
5. 사용자는 각 연결 역량에 현재 수준 1~5를 입력한다. 목표 수준은 입문 3, 기초 4, 실무 경험 있음 5로 제시한다.
6. `목표 수준 - 현재 수준`을 보완 필요 단계로 계산한다.
7. `hr_mapping_verified.csv`에서 선택 역량과 연결된 교육과정을 찾는다.
8. 보완 필요 단계가 큰 역량, 여러 선택 역량과 연결된 과정, 짧은 시수 순서로 상위 3개를 제시한다.

이 로직은 사용자의 선택과 저장소의 매핑 데이터를 설명 가능한 형태로 연결한다. 자동 진단이나 실제 성과 측정 결과를 주장하지 않는다.

## 6. 신뢰성과 한계

- `INCLUDED`는 프로젝트의 직무 적합성 검증 상태다. 교육기관의 품질 보증이나 수강 가능성을 뜻하지 않는다.
- 과정 정보는 수집 시점 이후 변경될 수 있다. 카드의 수집일과 원문 링크를 함께 제공하는 이유다.
- 완료 처리는 브라우저 세션 내 사용자의 기록이다. 수료증 발급, 실제 이수, 역량 향상을 증명하지 않는다.
- NCS 연결이 없는 자유 입력 업무는 추천 점수에 넣지 않는다. 이를 자동화하려면 별도의 검토·매핑 절차가 필요하다.
- 개인 정보는 서버에 저장하지 않는다. 현재 구현은 Streamlit 세션 상태만 사용한다.

## 7. 예외 처리와 이용 안내

- 데이터 로딩 중에는 진행 안내를 보여준다.
- 데이터 로딩 실패 시 새로고침, 데이터 파일 경로 확인, GitHub Issue 등록 방법을 안내한다.
- 업무를 선택하지 않으면 추천을 만들지 않고 필요한 입력을 설명한다.
- 직접 연결된 확정 과정이 없으면 검토 대기 과정 탐색을 안내한다.
- 문의 및 개선 제안은 GitHub Issues에서 받는다.
- 모바일에서는 표와 차트가 넓어질 수 있으므로 과정 탐색 표의 가로 스크롤을 안내한다.

## 8. 운영 및 갱신 원칙

1. 수집 파이프라인을 실행한 뒤 원문 URL, 수집일, 기관명, 일정·비용 필드를 점검한다.
2. 새 과정은 `INCLUDED`, `REVIEW_NEEDED`, `EXCLUDED` 상태를 명확히 기록한다.
3. 새 직무나 업무를 추가할 때는 `jobs.csv`, `competencies.csv`, `job_competencies.csv`를 함께 갱신한다.
4. NCS와 직접 연결되지 않는 업무는 검토를 거친 뒤에만 추천 대상에 추가한다.
5. 배포 전에는 `uv run python -m py_compile app/streamlit_step4.py`와 대시보드 수동 점검을 수행한다.

## 9. 발표에 사용할 핵심 수치

- 교육과정 후보: 553건
- 직무 적합 확정 과정: 295건
- 수집 방식: 공개 API 140건, 플랫폼 수집 데이터 413건
- 원문 플랫폼: 9개
- 직무 마스터: 6개
- NCS 핵심 역량 마스터: 7개

이 수치는 저장소의 현 시점 데이터 파일에서 계산한 값이며, 데이터 갱신 시 함께 다시 산출해야 한다.
