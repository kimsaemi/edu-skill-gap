## 3. 기존 코드, 데이터, 보고서 사이의 정합성 불일치 분석

### 3.1 불일치 1: `competencies.csv` 내 `ncs_unit_code` 기재 오류
- **문제점**:
  - `competencies.csv`에서 `COMP_HR_01` (인력채용)의 세분류 코드로 `02020201_16v3`이 기재되어 있었으나, 공식 표준상 `02020201`은 **총무** 세분류 코드입니다. (올바른 인사 코드는 `02020101`)
  - `COMP_GA_01` (문서작성 및 기획)의 세분류 코드로 `02010101_16v3`이 기재되어 있었으나, 공식 표준상 `02010101`은 **경영기획** 세분류 코드입니다. (올바른 코드는 `02020202` 일반사무 또는 `02020201` 총무)
- **원인**:
  - 초기 파일 작성 시 NCS 표준 분류 코드(직무 분류)와 능력단위(Competency Unit) 번호 사이의 매핑이 교차 혼입됨.

### 3.2 불일치 2: 공공 API 수집 데이터의 부동소수점 코드 변환 문제
- **문제점**:
  - 기존 140건의 공공 API 수집 데이터에서 `ncs_code` 컬럼에 `2020201.0`, `2020101.0`, `2010101.0` 형태로 저장되어 있었음.
- **원인**:
  - 원본의 8자리 문자열(`02020201`)이 판다스(pandas) 수집/저장 과정에서 숫자형(`float64`)으로 자동 변환되면서 맨 앞의 `0`이 탈락하고 `.0`이 붙는 포맷 훼손이 발생함.
- **조치**:
  - `ncs_code_type`을 신설하여 공식 8자리 코드 복원 포맷(`OFFICIAL_NCS_CODE`)과 자체 프로젝트 ID(`PROJECT_CUSTOM_KSA_ID`)를 명확히 분리함.

### 3.3 불일치 3: 'VERIFIED' 표기의 의미와 규칙 기반 오매핑(False Positive) 109건
- **문제점**:
  - 일부 보고서에서 `VERIFIED 3,595건`을 "검증 완료된 데이터"로 표현하여 사람의 정성 검증을 마친 것처럼 오해를 불러일으킴.
- **실제 사실**:
  - `VERIFIED`는 100% 키워드 룰셋에 기반한 **'규칙 기반 자동 매핑 후보'**에 불과함.
  - 전수 검사 결과, '파이썬', '자바', 'AWS 클라우드' 등 IT/개발 강좌가 제목에 '관리', '업무' 단어가 포함되었다는 이유로 `COMP_GA_01`로 잘못 매핑된 사례가 **109건** 실존함.

## 4. 정합성 확보 원칙 및 임베딩 적용 가이드라인

1. **공식 미검증 매핑 상태 유지**:
   - 사람이 직접 전수 라벨링하지 않은 모든 매핑은 '미검증 자동 매핑 후보(Rule-based Auto-matched Candidate)'로 명시하며, 임의로 '검증 완료' 처리하지 않습니다.
2. **NCS 코드만으로 임베딩 정답 데이터 생성 금지**:
   - "NCS 코드가 동일하다고 해서 두 교육과정이 실제로 유사하거나 적합하다"고 가정하지 않습니다.
   - IT/개발 오매핑 사례(109건)처럼, 잘못 매핑된 코드를 정답(Ground Truth)으로 삼아 모델을 평가할 경우 심각한 확증 편향(Confirmation Bias)이 발생하므로, 임베딩 평가는 독립된 15대 실무 질문 및 팀원 블라인드 평가를 기준으로만 수행합니다.
