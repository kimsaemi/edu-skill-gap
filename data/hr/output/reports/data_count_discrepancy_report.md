### 1-2. 수치 불일치 원인 상세 분석
Git 변경 이력(`git log`) 및 파이프라인 생성 스크립트(`scripts/run_step4_eda_pipeline.py`)를 역추적하여 원인을 정확히 규명하였습니다.

1. **사용된 데이터 파일 버전은 완전히 동일함**:
   - 두 보고서와 대시보드 모두 동일한 커밋(`0ba75df`) 시점에 구축된 `hr_integrated_candidates.csv` (553건) 및 `hr_integrated_verified.csv` (295건)을 기반으로 동작했습니다. 데이터 재분류나 파일 재생성으로 인한 버전 불일치가 아닙니다.
2. **파이프라인 스크립트 내 마크다운 텍스트 '하드코딩' 오류**:
   - `scripts/run_step4_eda_pipeline.py` 실행 시 실제 연산 코드는 `pd.crosstab(...)`을 통해 `table_q0_platform_status_crosstab.csv`를 생성하였으며, 여기에는 정확한 수치(**HUNET 65, KPC 62, KMA 39, GSEEK 17, MULTICAMPUS 11**)가 기록되었습니다.
   - 그러나 스크립트 하단의 보고서 출력부(`report_content = f"""..."""`) 작성 과정에서 변수 바인딩 대신 **초기 검토 단계의 가안 수치(98, 44, 33, 16, 3)가 텍스트 블록에 수기 하드코딩**되어 마크다운 문서로 내보내졌습니다.
3. **대시보드(`streamlit_step4.py`)의 집계 상태**:
   - 대시보드는 텍스트 보고서의 수치를 읽지 않고, `hr_integrated_candidates.csv`를 실시간 `groupby`하여 집계하므로 **최신 실측값(HUNET 65, KPC 62 등)을 정상 반영**하고 있습니다.
4. **결론**:
   - **현재 실측 데이터의 참값(Ground Truth)은 `hr_integrated_verified.csv`의 295건(휴넷 65, KPC 62, KMA 39, GSEEK 17, 멀티캠퍼스 11, 패스트캠퍼스 5, 고용24 96)입니다.**
